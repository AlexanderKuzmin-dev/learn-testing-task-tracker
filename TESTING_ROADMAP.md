# TESTING_ROADMAP — как научиться тестировать на примере Task Tracker

Task Tracker — учебный проект: React + TypeScript + Redux Toolkit + RTK Query, тестов в нём пока нет. Этот файл — маршрут по освоению стека **Vitest → React Testing Library → MSW → Playwright** на реальном коде репозитория. Открыл файл → понял, что делать → пошёл делать.

## Как пользоваться

1. Клонируйте репозиторий, `npm install`, запустите `npm run dev` и поиграйте с приложением: вход (подойдёт любой корректный email и любой непустой пароль), список, фильтры, добавление, правка, удаление, страница задачи.
2. Идите по этапам **последовательно**: каждый следующий опирается на инструменты и навыки предыдущего.
3. **Не пропускайте блок «Что почитать перед стартом»** в начале этапа — без него таблицы ниже превращаются в механическое заполнение чек-листа.
4. Отмечайте прогресс прямо в файле (`- [ ]` → `- [x]`) и коммитьте вместе с тестами — прогресс будет виден в git-истории.
5. В файле **нет тестового кода** — только план, ссылки и чекбоксы. Код пишете сами.

Все пути ниже — от `src/`. Сложность: **Низкая** — 10–20 минут, **Средняя** — час, **Высокая** — несколько подходов.

### Особенности кода, о которых полезно знать заранее

- `setupStore(preloadedState?)` в `app/store.ts` — **фабрика**: в каждом тесте создавайте свой чистый стор. Это же решает проблему кэша RTK Query между тестами.
- `routes` в `app/routes.tsx` — **массив**, а не готовый роутер: тесты собирают `createMemoryRouter(routes, …)`.
- Базовый URL API — `API_BASE_URL` из `app/config.ts` (`https://jsonplaceholder.typicode.com`). Его же используют MSW-хендлеры.
- JSONPlaceholder ничего не сохраняет: правки живут только в кэше RTK Query (`updateQueryData`, `upsertQueryData`).
- Задачи с `id > 200` (`SERVER_TODOS_COUNT`) созданы на клиенте — для них `updateTodo` **не ходит в сеть**.
- Вход **фейковый и локальный**: сетевого запроса при логине нет, состояние лежит в `authSlice` и дублируется в `localStorage` (`authStorage`, `authPersistence`).
- В `TodoStats` уже есть `data-testid` (`stats-total`, `stats-completed`, `stats-percent`) — пригодятся в e2e.
- `Modal` и `ConfirmDialog` не имеют пропа «открыт/закрыт»: они показываются, пока смонтированы. Показ и скрытие проверяются на уровне родителей (`DeleteTodoDialog`, `EditTodoModal`, `TodosContent`).
- `ErrorMessage` всегда рендерит переданный `message`; «нет ошибки — нет сообщения» решают родители (`TodosSection`, `TodoDetailPage`). Условная часть самого компонента — кнопка «Повторить» при переданном `onRetry`.
- `deleteTodo` в отличие от `updateTodo` **не проверяет** клиентские id: `DELETE` уходит в сеть и для задач с `id > 200`. Кэш `getTodoById` при удалении не трогается.
- `addTodo`, `updateTodo` и `deleteTodo` правят кэш только если он уже есть (`updateQueryData` без загруженного списка ничего не делает).
- `LoginPage` возвращает пользователя на `location.state.from.pathname` — только путь, без query и hash.

### Что тестировать не нужно

Отдельные тесты на эти файлы не нужны — они либо не содержат логики, либо покрываются косвенно: `features/todos/constants.ts`, `features/*/types.ts`, `app/config.ts`, `app/hooks.ts` (типизированные обёртки), `app/baseApi.ts` (пустой `createApi`, проверяется через эндпоинты), `main.tsx` (точка входа — покрывается e2e).

## Этап 0 — Подготовка окружения (один раз)

Сейчас в `package.json` нет ни одного тестового инструмента.

- [ ] Установить dev-зависимости: `vitest`, `jsdom`, `@testing-library/react`, `@testing-library/jest-dom`, `@testing-library/user-event`, `msw`, `@playwright/test`
- [ ] Настроить Vitest в `vite.config.ts` (или отдельным конфигом): среда `jsdom`, `globals`, файл `setupFiles`
- [ ] В setup-файле подключить `jest-dom`, очистку DOM после каждого теста и (позже, на этапе 3) запуск/сброс MSW-сервера
- [ ] Добавить в `tsconfig.app.json` типы для тестовых глобалов (`vitest/globals`, `@testing-library/jest-dom`)
- [ ] Добавить npm-скрипты: `test`, `test:watch`, `test:coverage`, `e2e`
- [ ] Договориться о расположении тестов: рядом с файлом (`Button.test.tsx`) — так их проще находить и поддерживать
- [ ] Создать общий тестовый хелпер «отрисовать с провайдерами»: `Provider` со свежим `setupStore(preloadedState)` + `MemoryRouter`/`createMemoryRouter`; возвращает и стор, чтобы проверять состояние
- [ ] Убедиться, что `npm run lint` и `npm run build` (tsc) проходят с тестовыми файлами

**Definition of Done:** `npm test` запускается и находит хотя бы один тривиальный тест; тип-чек и линтер не ломаются.
